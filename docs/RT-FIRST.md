# RT-first — the architecture, in build order

**Owner-set 2026-09-06 (late night).** After a week of per-effect rules on the reflection accumulator the owner said: "this is a game engine with RT capabilities and it should be generally good with RT stuff; the approach should be RT first now; if that means changes to the architecture, let me know" — and then "go for the architecture, in that order". This document is the plan. `docs/RENDERING-REVAMP.md`'s WR-16 R series is paused where it stands (R1–R3, R12 done; R4 shelved; R5 half-found); its R7, R8, R9, R10 become steps of this plan rather than items.

## 0 · One correction to the premise, and what is right in it

The owner's reading: "RT rendering needs to be a separate pipeline altogether; turning on ray tracing should swap the whole pipeline; raster-specific things should not be visible in RT mode; OpenGL and Vulkan part ways here."

**What is right.** RT mode is a different *set of passes* with a different settings surface, it is Vulkan-only (`RHICaps::SupportsRayQuery` is false on OpenGL, always), and the raster-only controls should be gone from the editor in RT mode, not greyed. All of that is in this plan.

**The correction.** No shipped engine (Unreal 5 with Lumen, Frostbite, id Tech) runs a *separate renderer* for RT. Primary visibility — what the camera sees first — is still rasterised into a G-buffer in both modes, because rasterising primary rays is far cheaper than tracing them and gives the same answer. What RT mode swaps is the **lighting**: shadows, ambient occlusion, global illumination and reflections come from rays instead of shadow maps, screen-space passes, voxels and probes. Materials, the water, transparency, TAA, tonemap, bloom, depth of field are shared. So the picture is: **one renderer, two lighting pipelines behind one switch, sharing the G-buffer and the post chain.** That is what this plan builds. Full path tracing of primary rays is a possible later mode (a "reference" mode for truth renders), not the game mode.

## 1 · Where the engine is

- **Forward.** The scene pass lights every pixel in one 6000-line fragment header (`pbr_fragment.glsl`); in RT mode it also traces the shadow rays and shades GI hits *inside* that shader. Nothing stochastic there has a reconstruction of its own; TAA is the catch-all.
- **A partial G-buffer exists.** The scene target already carries extra attachments: normal + roughness (`kNormalFormat`, read by the reflection passes), velocity, and an indirect target; there is a depth prepass (`PrepassSet`). What is missing for RT lighting passes to run *before* shading: albedo/F0/metallic, a material id, and the ordering (today these attachments are written *by* the lit pass, so no lighting pass can consume them before it).
- **Per-effect RT toggles** with a master `RenderSettings::RayTracing`: `RayTracedReflections`, `RayTracedAmbientOcclusion`, `RayTracedSkyVisibility`, `RayTracedGlobalIllumination`, `RayTracedWaterRefraction`, each Off / a detail level. The editor greys raster fields via `FieldHint::DisabledIf`; it can hide via `OnlyWhen(...)`, which is what the mode switch will use.
- **The one proper RT signal path** is the reflection pipeline built this week: trace (one ray, direction + pdf) → resolve (hit-point reuse) → accumulate (surface tests, silhouette rule, motion-capped memory, bound) → young-history blur → composite after TAA. It is the template for the contract in step 2.
- **GI** already has a trace target and `gi_denoise`; **AO** has `rtao_compute` and an SSAO-style accumulate; **shadows** have nothing of their own.
- **Light sampling at hits** is by chance (a ray must hit the tube's lens); WR-16's ReSTIR DI design (`docs/RAY-BUDGET-DESIGN.md`) and WR-8's LTC line lights are the two halves of fixing that.

## 2 · The plan, in the owner's order

### Step 1 · The G-buffer, and RT mode as a real mode

**Goal.** Every RT lighting signal can be computed in its own pass, before shading, from a G-buffer; the mode switch reconfigures the frame graph and the editor.

**Build.**
1. **A G-buffer prepass** that writes depth, octahedral normal + roughness (the existing `kNormalFormat`), albedo + metallic (RGBA8 sRGB), F0/specular where the material has it, velocity (existing), and a material/entity id (R16_UINT) for the denoisers' "same surface" tests. Opaque and alpha-cutout geometry only; the water and transparency stay forward and draw after lighting as today. This extends the existing depth prepass rather than adding a fourth geometry walk.
2. **The lit pass consumes signals instead of computing them.** In RT mode the lit shader reads four textures — shadow visibility, AO, diffuse GI, specular (reflections) — where today it traces shadow rays, reads the AO/GI results, and calls the reflection hook. The direct-lighting evaluation (the BRDF, the light loop) stays where it is: a "forward+ with a G-buffer" design, which keeps the material system, layered materials, cutouts and the water untouched. Full deferred shading is *not* proposed: it would rewrite the material path for no RT gain.
3. **`RenderSettings::RenderMode { Raster, RayTraced }`** replaces the `RayTracing` bool as the project's one switch. Raster mode: shadow maps, SSAO, SSGI/voxel/probes, SSR. RT mode: every one of those replaced by its RT pass; no mixing (per-effect RT toggles go; a detail *level* per signal stays, as the RT optimisation preset's columns). The frame graph builds one pass set or the other. OpenGL: RT mode unavailable, the editor says why.
4. **The editor's settings surface** — raster-only fields are `OnlyWhen(RasterMode)`, RT-only fields `OnlyWhen(RayTracedMode)`, shared fields always. Hidden, not greyed. The split (to confirm with the owner): raster-only = shadow maps and cascades, SSAO, SSGI, voxel GI, SSR, the probe volumes' runtime capture; RT-only = the ray preset, per-signal detail, denoiser settings, the ray budget; shared = TAA/AA, exposure, bloom, DoF, fog, tonemap, motion blur, sky, materials, lights (with `CastShadows` meaning shadow map in one mode and shadow rays in the other).

**Verify.** Raster mode renders pixel-identical to today (the prepass writes what the lit pass wrote; no lighting change) — per-pixel diff on the garage and the bridge, zero. RT mode renders identical to today *before* step 2 (the lit pass still traces internally until each signal migrates). Frame cost of the prepass measured (expected: a fraction of a millisecond, the depth prepass already walks the geometry). The editor shows no raster field in RT mode and vice versa.

**Effort.** One to two weeks. **Traps.** The bindless material path and layered materials must write the G-buffer the same way the lit pass shades them (one `SampleSurface`); the alpha-cutout prepass must match the lit pass's cutout exactly or edges shimmer; the water reads the scene depth, keep the ordering; saved projects carry `RayTracing: true/false` — migrate to the mode on load.

### Step 2 · One reconstruction contract for every stochastic signal

**Goal.** Shadows, AO, GI and reflections each are: a trace pass at one ray per pixel (or fewer), then the same denoiser, then a stable texture the lit pass reads. Written once.

**The contract** (the reflection accumulator is the template, generalised):
- **Input:** the signal (RGB or scalar), its hit distance, the G-buffer.
- **Reproject** by the surface (and, for specular, by the virtual image as the accumulator does); **tests:** normal, plane, material id, roughness; **the silhouette rule** (history kept across the jitter flip) with the motion term; **hit-distance validation** (the R5 finding: a reflected or occluding object that moved changes the hit distance, and that is how a still surface's history is caught out) restricted to same-surface neighbours; **memory** = min(64 / (1 + moved / slack), kSmearTexels / moved, hit-distance-shortened), floor per signal; **a bound** from the fresh neighbourhood and the temporal moments; **a young-history blur** (a-trous, radius from the history length, bounded by the signal's own footprint — the lobe for specular, a fixed few texels for shadows).
- **Output:** the denoised signal + history length + confidence, for the lit pass and the debug views (history length, refusal reason, reach — R6, done once for all).
- **Order of migration:** shadows first (the largest cost and the wall's motion noise: one visibility ratio per pixel toward a chosen light, Heitz's ratio estimator), then AO (merge `rtao_compute` + the SSAO accumulate into the contract), then GI (audit `gi_denoise` against the contract, replace), then reflections (already the contract; it becomes an instance of the shared code).

**Verify.** Per signal: the reflections-off dolly arm's wall change (5.5 a frame today) falls toward the parked floor after shadows migrate; a still frame against a brute-force reference; the parked/edge/settle metrics unchanged for reflections. Frame cost per signal in the bench's columns.

**Effort.** One to two weeks after step 1. **Traps.** Two temporal systems on one signal (the denoiser and TAA) — measure the pair; flashing emitters (the bridge's beacons) must reset every history (the Ground rules); the ratio estimator's division.

### Step 3 · Direct light sampling at ray hits

**Goal.** Emitters are sampled on purpose. The grain every denoiser fights comes from rare bright hits; removing it at the source is what lets memories be short and blurs be small — the residual smear R12 left is this.

**Build.** (a) Emissive geometry becomes lights the tracer can sample: the tubes as line lights (LTC for the specular term, WR-8; the rays skip their lens emission, no double count), the bridge's lamps as what they already are. (b) ReSTIR DI (WR-16 M4, `docs/RAY-BUDGET-DESIGN.md`) for the many-light shadow problem: one shadow ray per pixel toward a resampled light, feeding step 2's shadow denoiser. (c) The same resampled light at GI and reflection hits (NEE at the hit).

**Verify.** The unclamped converged truth of each scene against the new build (bias within the truth's grain), then HF energy, settle, and the moving-frame error (19–20 today for the floor; the target is within a few levels of parked). The bridge's ~15 ms of shadow rays against the one-ray design.

**Effort.** One to two weeks. **Traps.** Bias in resampling weights (a plausible picture with wrong weights is the silent failure); boiling; correlation with TAA.

## 2d · T5 — Direct light as a signal on the contract (design, 2026-09-06; owner said "go for T5, if this affects ray budgeting then let me know")

**What the engine does today, measured on the garage (1600x900, Quality, T4 build):** the lit fragment shader walks the cluster cell's light list -- 27 lights per pixel on average, 30 in the scene, 23 casting -- and traces **one soft-shadow ray per casting light per pixel**: 24.47 M shadow rays a frame, 17 per lit fragment, and `scene/Scene` at 4.84 ms is the largest pass of the 11.6 ms frame. Nothing reconstructs the direct light temporally; only TAA integrates the per-frame disc sample, which is why a moving camera shows the wall's motion noise (the TAA history is invalid exactly where the disc sample changes). The bridge is the same shape at 78 lights and ~15 ms. WR-17 thins far lamps by distance (a no-op at garage scale); S1's `--shadow-budget=K` and S4's `--light-sampling=K` sampler exist inside the loop but the sampler engages only where the irradiance field owes nothing (`fieldWeight <= 0`) and the cell holds more than 2K lamps -- off on the garage floor, which sits under its volume.

**The precedent already in the engine:** WR-16 S4 built exactly this architecture for the sea -- a surface prepass, `water_choose` (K reservoirs per pixel by weighted reservoir sampling on a cheap target), `water_shade` (the K survivors shaded in full, one shadow ray each), `water_accumulate` (the *light* averaged over frames, not the choice -- the choice reuse was measured to lose), and the water draw adding two textures instead of walking the lamps. T5 is that pipeline for every opaque pixel, fed by T1's G-buffer and denoised by T4's contract instead of the water's own accumulate.

### The passes (between "GBuffer" and "Scene")

1. **`DirectTrace`** (fullscreen, `RV_TRACE_ONLY` over the lit shader as `rtgi_trace` and `water_shade` do; reads the G-buffer: depth, `o_Surface` = oct normal + roughness + metallic, `o_Albedo` = albedo + specular scalar, `o_SurfaceId` whose **sign carries the Static flag**). Per pixel: reconstruct the surface (`view_reconstruction.glsl`), find its cluster cell (a `ClusterCellAt(worldPos, uv)` that needs no varyings), walk the cell's 16-byte cull records (`LightCullRejects`), and **keep K lights by weighted reservoir sampling** on S4's target 1 -- the unshadowed irradiance times the BRDF's magnitude (diffuse albedo luminance over pi plus the GGX lobe's peak; the sampler's own score at the lit shader's line ~4545). The **directional lights are always shaded** (there are at most a few; they are not in the cell). Each survivor: the full BRDF exactly as the lit loop computes it (kD, Fresnel, Smith), `liveShare` for the baked-field split (`BakedShare`, the same function), **one soft shadow ray** (`TraceShadowSoftFromMasked`, the light's `kind`/CastShadows exemption kept -- the lesson of S4b), its light divided by its selection probability over K. Choose and shade are **one pass, in registers** -- no reservoir textures, no neighbour pass; the temporal/spatial reuse of choices is T10's (ReSTIR DI), and on the water it measured as a loss. Two outputs, R16G16B16A16_SFLOAT:
   - `DirectDiffuse`: sum of kD x radiance x cos x visibility x liveShare -- **the albedo demodulated** (the lit shader multiplies by albedo / pi), so the denoiser blurs light and never texture;
   - `DirectSpecular`: sum of specular x NdotL x radiance x visibility x liveShare, complete.
   - `.a` = 1 on a lit surface, -1 on sky/empty (the contract's "no surface" flag).
2. **`DirectAccumulate` + `DirectBlur` x3**: T4's contract with `SignalParams{ Diffuse, Slot 1 }` -- surface reprojection, the normal/plane/roughness tests, the silhouette rule, the motion-capped memory, the mean +- 3 sd bound (a switched light falls outside the bound everywhere and the history drops in one frame, which is R9's 47-level lag answered structurally), the young-history blur bounded by `MaxRadius`. **The contract gains a second payload** (`RV_SIGNAL_PAIR`: a fourth accumulate attachment, a second blur attachment, `fresh2`/`history2` inputs) so the diffuse and specular halves share one set of surface tests, one refusal reason and one blur radius; the reflection instance passes null and compiles as before. One memory for both halves in the first landing; a per-payload memory (the water's glint needed a short one) only if the highlights smear under camera motion -- measured, not assumed.
3. **The lit pass consumes it.** Under a new define `RV_DIRECT_SIGNAL` (pushed with `RV_RAY_SHADOWS` when the signal runs) the opaque lit shader's light loop keeps **only the subtractive branch** -- a static surface under a fully baked lamp with a moving object in range traces its one moving-only ray and the loss is clamped against the field's stored direct light exactly as today, because `storedDirect` lives in the lit shader and the case is rare and cheap -- and adds the two textures: `Lo += diffuseTex * albedo / PI + specularTex` (bound at set 0, bindings 26 and 27). The `directIrradiance` pre-loop, WR-17's thinning, S1's reservoirs and S4's in-loop sampler all fold away under the define. The water keeps its own passes (they are this design already); transparent surfaces keep the in-shader loop (they are not in the G-buffer).

### What it costs and what it should give (estimates, to be measured)

Garage at K = 8 (Quality's `Lamps`): 1.44 M x 8 = 11.5 M shadow rays against 24.47 M; at K = 4, 5.8 M. The trace pass pays the cheap walk plus K BRDFs plus K rays; the accumulate and three blurs cost what the reflection's do (0.27 + 0.39 ms). The Scene pass loses its light loop -- its largest loop, and the register pressure that comes with it. Expected: the frame's shadow work roughly halves at K = 8, and **the direct light has a temporal reconstruction for the first time**, which is the wall's motion noise. The bridge: K = 8 against 9.3 rays and 78 lights per fragment today.

### Ray budgeting -- what T5 changes (the owner's question)

1. **Shadow rays stop being one per light and become K per pixel.** The count is bounded and predictable for the first time -- 1.44 M x K -- which is the "shadow spender" WR-16's design named (Part IV, S4 "the proper way"). K is the preset's existing `Lamps` field (Quality 8, Balanced 4, Performance 2, Off 0 = every light, the old loop) and the existing `--light-sampling=K` override; **no new dial** (owner's rule: global render settings). The water reads the same K.
2. **WR-17's distance thinning, S1's `--shadow-budget` and S4's `--shade-lights` become dead for opaque surfaces.** The sampler thins by contribution, which is the "Share" shape the owner's own rule called the physical form. They stay in the code under the old path (`--direct-signal=off`), which is the A/B and the truth arm.
3. **The per-tile K lane in the allocator (S3's widening: "the shadow-ray ceiling, S4's K per tile") is not built in T5.** Part IV decision H's reasoning holds: build the consumer first, then size the lane for it.
